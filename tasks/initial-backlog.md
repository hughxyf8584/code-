# 首批实施任务

建议从上到下推进。每项任务都应产出可检查的文件或结果；开始前先使用合成或已批准的数据。

## P0 — 本地环境与项目骨架

**目标：** 在本机建立可重复的 Python 开发环境。

**步骤：**
1. 安装 Python 3.11 或更高版本。
2. 按 README 创建并激活虚拟环境。
3. 执行本地可编辑安装和导入命令。

**验收：** python -m pip install -e . 成功；导入 epc_ai_lab 成功并显示版本 0.1.0。

## P0 — 定义周度进度数据口径

**目标：** 固定首个实践的数据粒度和字段定义。

**建议字段：**

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| report_date | 周报数据日期 | ISO 日期格式 |
| block_id | 区块编号或脱敏代号 | 非空 |
| activity | 工作项，如 tracker、module | 受控名称 |
| planned_pct | 该粒度的计划完成百分比 | 0–100 |
| actual_pct | 该粒度的实际完成百分比 | 0–100 |

**验收：** 明确重复记录的处理、缺失值与零值的区别、偏差正负号（实际减计划），以及未来汇总使用的权重依据。

## P1 — 建立合成样例与输入校验

**目标：** 准备一份不含真实项目敏感信息的小型 CSV，用于开发和复核。

**步骤：**
1. 构造至少两个报告日期、三个区块和三类工作项的合成记录。
2. 为日期、百分比范围、必填字段和重复键定义校验规则。
3. 对错误输入给出具体行号与原因。

**验收：** 合成数据能覆盖计划领先、落后、相等、缺失和非法百分比等情况；错误能被发现而不是静默改写。

## P1 — 实现可追溯的偏差汇总

**目标：** 输出每个区块和工作项的计划、实际、偏差及数据日期。

**步骤：**
1. 先用清晰的 Python 函数实现计算。
2. 复核偏差公式为实际百分比减计划百分比。
3. 在权重口径确认前，不生成一个看似精确的总体项目进度数字。

**验收：** 每个输出值都能追溯到输入记录与计算规则；正偏差表示领先，负偏差表示落后。

## P2 — 生成周度图表与简报

**目标：** 将校验通过的结果转成便于项目周会使用的图表和摘要。

**建议图表：** 计划与实际趋势、区块偏差排序、数据缺口提示。

**验收：** 图表显示数据日期、单位、偏差方向和数据来源；报告不掩盖未完成或无效数据。

## P3 — 加入有边界的 AI 辅助

**目标：** 在确定性分析稳定后，评估资料检索或解释草稿功能。

**验收：** AI 解释能引用输入指标或获准资料；不能自行更改计算值、合同立场或工程结论；涉及决策的输出由负责人复核。
